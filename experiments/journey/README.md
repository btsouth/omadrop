# Journey study

Osaka Jade to Kanagawa, rendered on the GPU. One OpenGL 3.3 core code path
serves the native Qt Quick preview (`QQuickFramebufferObject`) and headless
export (surfaceless EGL with framebuffer readback; no display). See
[the direction](DIRECTION.md). This is a study, not accepted artwork or a
product integration.

Requires Qt 6.4+ Core/Gui/Qml/Quick/OpenGL, qmake6, a C++17 compiler, FFTW
single precision (`fftw3f`), libEGL and libOpenGL (GLVND). Build and export on
devbox; run native previews only inside an isolated omabox desktop.

```sh
mkdir -p build && cd build
qmake6 ../journey.pro
make -j8
```

## Renderer

- `canvas.*`: a small cairo-like vector canvas. Paths are flattened and
  tessellated on the CPU in design pixels (1920 x 1080) and drawn with 8x
  multisampling (4x above 1080p). Convex fills draw directly; other fills use
  the stencil nonzero rule; translucent strokes draw each sample once.
  Linear and radial gradients and soft glow sprites are evaluated per pixel.
- `gpu.*`: a half-float compositor. Canvases draw over or add into the image,
  optionally through an offscreen layer with blur, gain and opacity, like the
  approved mock's layers. Full-screen passes add sky, the disc, haze bands,
  fog, steam and street reflections. `finish()` applies bloom, vignette, the
  soft knee, paper grain and film grain, then the title.
- `rig.*`: silhouette figures with two-bone IK, a gait whose stance foot stays
  planted in world space, cats and birds.
- `osaka.cpp`, `crossing.cpp`, `kanagawa.cpp`: the worlds and their
  timelines. `score.*` measures onsets, bass hits, mid peaks and surge starts
  once from the analysed audio, so every frame is a pure function of time.
- `title.cpp`: theme titles from fixed JetBrains Mono outlines
  (`caption-assets/title-outlines.inc`, generated by `title_generate.py`).

The current ending runs through movie second 83. The large wave travels
from the left, spills branching cream foam and breaks the near boat on a
measured onset. Its crew hold floating planks and the surviving boat collects them. The bearer
washes onto the beach, recovers his glowing lantern and walks to an 80s coupe
on a violet mountain road. He boards, the door closes and the car follows
the bend toward the Tokyo Night title. The full next chapter is still to come.

For a focused preview, use `--start 48 --duration 83` with
`--fade-in 0 --fade-out 0.5`. This exports a 35-second section with the matching audio;
`--duration` remains the absolute ending movie time. JPEG exports also
support `--start`, so response checks can render only their affected window.
The CLI default ending remains 60 seconds. Keep the 14 ms 1080p frame budget
on the RTX 4070 SUPER.

## Usage

Native preview inside omabox:

```sh
build/omadrop-journey --audio /path/song.f32 --audio-offset 168.8 --duration 83
build/omadrop-journey --audio /path/song.f32 --audio-offset 168.8 --at 36 --paused
```

| Key | Action |
| --- | --- |
| Esc / Q | Quit |
| Space | Pause / resume |
| Left / Right | Scrub one movie second |

Headless export:

```sh
# Focused H.264 + AAC section at 60 fps, movie 48 to 83.
# The matching soundtrack and optional fades are muxed from the same fixture.
build/omadrop-journey --audio song.f32 --audio-offset 168.8 --start 48 --duration 83 --fade-in 0 --fade-out 0.5 --fps 60 --video out.mp4
# PNG stills at chosen movie times.
build/omadrop-journey --audio song.f32 --audio-offset 168.8 --duration 83 --stills 10,38,58,63.92,64.49,65.2,74.5,77.8 --out-dir stills
# JPEG frame sequence (frame i samples start + i / fps; existing files need --overwrite).
build/omadrop-journey --audio song.f32 --duration 30 --export-dir frames --fps 30
# Frame timing without output; per-second audio report for choosing an offset.
build/omadrop-journey --audio song.f32 --audio-offset 168.8 --duration 83 --bench 25,38,58,64.49,65.2,74.5,77
build/omadrop-journey --audio song.f32 --inspect
```

`--start S` renders only movie seconds `[S, duration)` with `--video`, and
`--fade-in` / `--fade-out` set the fades in seconds (0 disables), for cutting
segments on the music's bar lines.

`--seed` varies details of the authored timeline (window wake times, bird
order and approach). `--at` and `--paused` are native-only.

Audio input is headerless interleaved stereo 44100 Hz float32 little-endian
PCM (`ffmpeg -i song.mp3 -ar 44100 -ac 2 -f f32le song.f32`). The analyser in
`audio.cpp` is unchanged: six frequency roles (25..70, 70..150, 150..400,
400..1500, 1500..4000, 4000..12000 Hz), bass body, onset accent and a surge
envelope with a six-second cooldown, warmed from sample zero. Omitting
`--audio` renders silence; the worlds stay alive and the surge windows use
their fallbacks. Invalid input fails as before.

Focused audio checks:

```sh
mkdir -p build-tests && cd build-tests
qmake6 ../tests/audio_tests.pro && make -j4 && ./journey-audio-tests
```

No live PipeWire, product backend, website, installer or desktop
configuration is changed by this study.

## Direction stills

`--direction-study --stills 56.8,64.2,69.5,77.5` previews four proposed
compositions in the same live Canvas/GPU renderer: wave buildup, peak curl,
crew rescue after the wreck, and the bearer approaching a retro coupe with
its passenger door open. Use the usual audio offset, output directory and
1080p settings. These studies are available only for stills and benchmarks;
they do not implement the crash, rescue, camera or pickup animation. Ordinary playback and exports use the animated wave, rescue and car pickup.
The study flag preserves the older proposed compositions. Both paths preserve
the opening and crossing before movie second 48.
